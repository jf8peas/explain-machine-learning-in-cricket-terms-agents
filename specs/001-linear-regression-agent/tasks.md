# Tasks: Linear Regression Agent App

**Input**: Design documents in `specs/001-linear-regression-agent/` (plan.md, spec.md, data-model.md, research.md, contracts/, quickstart.md)
**Tests**: Included, because plan.md specifies a full testing strategy (pytest, Vitest, Playwright).
**Organization**: Grouped by user story so each can be built and verified on its own.

## Format: `- [ ] [ID] [P?] [Story?] Description with file path`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1 to US7, from spec.md
- Paths are relative to the repo root. `APP` = `apps/linear_regression`.

## Path Conventions

Backend: `APP/backend/linreg/`. Web: `APP/web/src/`. Backend tests: `APP/tests/`. Web tests: `APP/web/tests/`.

## Dependencies and Execution Order

- **Phase 1 (Setup)** has no dependencies.
- **Phase 2 (Foundational)** depends on Phase 1 and blocks all stories. Within it: T008 → T009 → T010 → T011; T012 to T017 are parallel; T018 needs T012 to T017; T019 needs T018; T020 to T022 need T019; tests T023 to T026 can be written alongside, then T027.
- **US1** needs only T022 (structure endpoint). It is the MVP. T032a (Playwright harness) must finish before any Playwright task (T033, T043, T049, T054, T061, T066, T070, T071).
- **US2** needs US1 (component shell) and the run endpoint.
- **US3** and **US4** both build on US2's buffer and can proceed in parallel after it (different parts of the component).
- **US5** needs Phase 2 (the routing logic itself is built in T018 and T019; this phase verifies it and adds the comparison view) and benefits from US2 and US4 for its UI test.
- **US6** needs Phase 2; its page rendering (T065) needs US4's panels.
- **US7** needs a completed run (US2) and the final state (US6 not required).
- **Polish** comes last; T071 and T072 can start after US2.

```text
Setup → Foundational → US1 → US2 ┬→ US3
                                 ├→ US4 ──→ US6
                                 ├→ US5
                                 └→ US7 → Polish
```

## Implementation Strategy

1. **MVP**: Phases 1 to 3. The page shows the whole agent drawn from the live structure endpoint.
2. **Core experience**: add US2, US3 and US4 (all P1). This is the complete step-by-step viewing experience.
3. **Learning payoff**: add US5 and US6 (P2), then US7 (P3).
4. Run the polish phase before any public release. SC-007 and T072 matter most for reuse by the other seven apps.
