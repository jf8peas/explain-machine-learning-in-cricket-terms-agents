# Data Model: Linear Regression Agent App

## Innings record (`data/innings.csv`)

One row per first innings.

| Field | Type | Rule |
|---|---|---|
| match_id | string | Cricsheet match id; unique per file (first innings only) |
| match_date | date (ISO) | Required; drives the calendar-year split |
| season | string | As given by Cricsheet (e.g. `2023/24`); informational |
| competition | enum | `t20i`, `ipl`, `bbl` |
| venue | string | Informational; not a model input |
| runs_at_10 | int ≥ 0 | Cumulative runs after over index 9 |
| wickets_at_10 | int 0–9 | Cumulative wickets after over index 9 (all out before 10 overs is excluded) |
| powerplay_runs | int ≥ 0 | Runs in over indexes 0–5; ≤ runs_at_10 |
| final_total | int ≥ runs_at_10 | Innings total |

**Excluded at preparation**: no-result, D/L or DLS, reduced overs, super overs, women's matches, and innings that ended before 10 overs were completed (including innings all out, 10 wickets, by the end of the 10th over, which is why `wickets_at_10` is 0–9). Counts before and after each exclusion are in `manifest.json`.

## Manifest (`data/manifest.json`)

`download_date`, `sources[]` (competition, URL), `counts` (matches read, innings kept, and the number removed by each exclusion), `attribution` (text shown in the UI).

## Run state (`RunState`, a `TypedDict`)

| Key | Type | Set by | Notes |
|---|---|---|---|
| summary | str | every node | Last node's plain-language summary; stripped from `changes` and accumulated state |
| data_summary | {innings, seasons, competitions, years, by_competition} | load_data | |
| data_error | str or null | load_data | Non-null routes to `stop` |
| explore | {corr_runs_final, slope_by_wickets, mean_total_by_competition} | explore | informational |
| split | {train_n, test_n, test_year, train_years} | split | |
| baseline_mae | float | baseline | mean absolute error in runs |
| features | list[str] | start, tune | Starts `["runs_at_10"]`; order from `FEATURE_ORDER` |
| coefficients | {feature: float} | fit_model | |
| intercept | float | fit_model | |
| feature_iqr | {feature: float} | fit_model | Interquartile range of each fitted feature in the training data; needed for importance ranking (coefficient × IQR) so the explanation uses state values only |
| model_mae | float | evaluate | |
| r2 | float | evaluate | |
| attempts | list[Attempt] | evaluate (append) | One per fit |
| decision | {branch, reason} | evaluate, load_data | `branch` in `ok`, `stop`, `tune`, `explain` |
| explanation | {sentences[], most_important, comparison} | explain_in_cricket_terms | Built from state only |

**Attempt**: `{features: list[str], mae: float, r2: float}`.

**Constants**: `MARGIN_RUNS = 3`; `FEATURE_ORDER = [runs_at_10, wickets_at_10, powerplay_runs]`; `MIN_TEST_INNINGS = 100`.

## State transitions

```text
load_data ──ok──▶ explore ▶ split ▶ baseline ▶ fit_model ▶ evaluate ──explain──▶ explain_in_cricket_terms ▶ END
   └─stop─▶ END                                   ▲            └──tune──▶ tune ┘
                                                  └──────────────────────────┘
```

- `evaluate` → `tune` iff `baseline_mae - model_mae < MARGIN_RUNS` and `len(features) < len(FEATURE_ORDER)`; otherwise `explain`.
- Maximum fits = `len(FEATURE_ORDER)` = 3.

## Step event (stream)

`{step: int ≥ 1, node: string, summary: string, changes: object}`. See `contracts/step-event.schema.json`.

## Graph structure (API)

`{nodes: [{id, kind}], edges: [{source, target, conditional, branch}]}` where `kind` is `start`, `end` or `node`. See `contracts/structure.schema.json`.

## Explanation

`sentences[]` generated by templates over state values only. Contains: most-important-feature sentence (coefficient × IQR), per-wicket cost sentence (when `wickets_at_10` is in the model; honest wording if the coefficient is not negative), error comparison against the broadcaster's projection, and a margin verdict sentence (cleared / did not clear 3 runs; beat / did not beat the baseline).
