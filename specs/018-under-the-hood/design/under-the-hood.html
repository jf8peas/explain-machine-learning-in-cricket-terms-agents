How this app was built

The question it answers, the data it learns from, what happens when you press Play, and how the answer reaches the page.

The question 1 · The data 2 · Pressing Play 3 · Inside the agent 4 · What you see 5 · Shipping it

The question

Halfway through a T20 first innings, the broadcaster projects the final total as run rate × 20 overs. This app builds a linear regression that tries to do better, and lets you watch it being built.

The goal

Miss the real total by at least 3 runs less than the TV, on average, on a season nothing was learned or chosen from.

The method

A language model proposes candidate models. A mechanical grid search competes with it. Code fits and scores every one.

The show

The work runs as a LangGraph agent. The page replays it step by step, then explains the result in cricket terms.

One rule runs through the whole build: the language model chooses and words things, but every number comes from code.

The big picture

Your browser

A static page, bundled with Vite. It asks for data, replays the run and draws every chart.

web/

A Python function on Vercel

FastAPI with six GET routes. It runs the LangGraph agent and streams each step back.

api/ + backend/linreg/

Two data files

innings.csv and overs.csv ship inside the function. They are read, never written.

data/

Done beforehand, by hand: a script turns Cricsheet's ball-by-ball files into the data files. During a run, two outside services help: OpenRouter relays calls to the chosen language model, and Upstash Redis holds the run limits.

Part 1

The data, prepared before anyone visits

From Cricsheet to two tables

scripts/prepare_data.py downloads three zips, reads every men's match and keeps the first innings when it can be predicted fairly. It drops 323 matches:

  • DLS, 184: rain changed the overs or the target, so the total is not a normal 20-over score.
  • No result, 100: the match was abandoned, so the innings may have been cut short.
  • Ended before 10 overs, 28: all out or stopped early, so there is no 10-over score.
  • Reduced overs, 11: scheduled for fewer than 20 overs, so run rate × 20 does not apply.

It writes innings.csv (one row per innings) and overs.csv (the score after every over). Data downloaded 17 October 2026.

Each innings becomes 19 candidate features

Fourteen measured at the end of over 10

  • Runs at 10 overs
  • Wickets at 10 overs
  • Powerplay runs
  • Powerplay wickets
  • Runs in overs 7 to 10
  • Wickets in overs 7 to 10
  • Fours hit
  • Sixes hit
  • Dot balls faced
  • Extras conceded
  • Current partnership runs
  • Balls since the last wicket
  • Batting team a full member
  • Bowling team a full member

Five worked out from those

  • Wickets in hand
  • Runs at 10 overs × wickets in hand
  • IPL (0/1) and BBL (0/1)
  • Both teams full members

Why 0/1? A regression only does arithmetic, so the competition becomes two yes/no columns. A T20 international is 0 in both.

Who is predicted: 2,872 of 5,209 innings

Every IPL and BBL innings, plus T20 internationals where both teams are ICC full members. Only these are scored; other internationals can still be learned from.

Part 2

What happens when you press Play

The page makes a few calls; only Play runs the agent

WhenCallWhat happens
The page loads/api/structure, /api/models, /api/catalogue, /api/referenceThe graph's shape, the model list, the features and the figures for the chart at the top.
You press Play/api/run?model=…The run limits are checked, then the agent runs and streams one event per finished step.
You open the Data tab/api/dataAll 5,209 innings, the column definitions and a summary.
Step, Back, sort, filter, PredictNoneDone in your browser on data it already has.

FastAPI is the doorway: a Python web framework that turns ordinary functions into web addresses, so a browser can ask Python to run the agent. It streams results as they happen, and Vercel can run it directly.

On the server, after you press Play

  1. 1Vercel receives the request and hands it to the Python function.
  2. 2FastAPI finds the right function for /run.
  3. 3The gate says yes or no. Is the model on the list? One run at a time, 5 an hour per visitor, 300 a day for the site. A no comes back as a message, and nothing runs.
  4. 4The agent's graph runs, node by node.
  5. 5Each finished node is sent straight back to your browser while the next one runs.

Inside the agent

First, the eight stages any ML project goes through

The agent's graph: twelve steps, each tagged with its stage

5 · propose_features→ 5 · check_proposal→ 6 · fit_model→ 5 · evaluate ↺ loops back, up to six rounds

The number is the stage. Filled steps call a language model; the other ten are ordinary code.

Stage by stage

1 Prepare the dataload_data checks the data before anything else runs

On every run it checks that:

  • innings.csv can be read and has every column
  • no feature value is blank or not a number
  • every worked-out column matches its recipe
  • every 0/1 competition column matches its competition
  • each check season and the test season have at least 100 innings to score
All well: it reports 5,209 innings from 45 seasons and the run moves on.
Anything wrong: it says what, in plain English, and the run ends. No model is fitted or called.
2 Split the dataThree seasons to choose with, one to test

Validation chooses. Every candidate model is fitted once per check and scored on the mean miss over the three.

The test judges. 2026 is read once, after the choice is made, so it is the honest number.

Never at random: each season is predicted only from the seasons before it.

3 Understand the dataSummary statistics brief the language model

The explore step works out, from seasons before the test:

  • each feature's correlation with the final total
  • runs added after 10 overs, by wickets down
  • the average total by competition and by season
  • innings per competition per season

These figures go into every message to the language model, so it can reason with real numbers without seeing a single row. Nothing is fitted here.

On today's data, runs at 10 overs × wickets in hand tracks the final total most closely (correlation 0.75).

4 Frame the problemWhat counts as good: four methods, four measures

Four methods

  • The know-nothing guess: the average past total
  • The TV projection: run rate × 20 overs
  • The AI's candidate model
  • The rival's candidate model

Four measures

  • Average miss in runs
  • Share within 10 and within 20 runs
  • Miss as a share of a typical total
  • Bias: guessing too high or too low

The bar, on 2,133 past innings (2005 to 2022):

MethodAverage miss
Know-nothing guess23.9
TV projection22.5

Knowing the score at 10 overs barely helps the TV, which guesses 14.3 runs too low on average. The goal is to beat it by at least 3 runs.

5–6 Choose and fitTwo searchers propose candidate models; code scores them

A candidate model is four choices

ChoiceOptions
Features1 to 8 of the 19
Training windowAll seasons, or the last 10, 5 or 3
Recency weightingNone, gentle or strong
Training inningsTest population only, or all

The window and the weighting are hyperparameters: settings chosen before fitting.

The AI, up to six rounds. It proposes; code checks the rules, fits on the training years, scores on the three checks and reports back.

The rival, every combination. A grid search tries all 24 settings, with forward selection inside each, in about half a second.

The pick. The lower validation score goes forward; a tie goes to the AI. If the AI can't take part, the rival's pick goes forward alone.

7 Final assessmentOne test, once, on a season nothing was chosen from

An example run with the language model switched off, on the 171 test innings of 2026:

MethodAverage missWithin 10 runsBias
Know-nothing guess34.522.8%−20.0
TV projection21.433.9%−7.2
Our pick (the rival's)17.837.4%−1.1

3.6 runs (16.8%) better than the TV projection, which reaches the goal. Your run will differ: the AI's choices change from run to run.

8 Interpret and communicateCode works out the facts; the language model may only word them

Code builds five blocks from named facts about the run:

  • the verdict
  • a takeaway on run rate
  • a takeaway on what drives the total
  • a takeaway on the TV projection
  • a rule of thumb

The language model may reword the three takeaways, naming facts by name instead of writing numbers.

A reply with a digit, a word like "too low" or an unknown fact is rejected, and the plain wording stays.

Part 4

What you see on the page

Each step arrives as a small event while the agent is still working. Your browser keeps them and replays them at a readable pace, so you can pause, step back and jump without running the agent again.

VALIDATION

Model Selection

How the choice was made, on the three check seasons: the contest, how each candidate is scored, the race, the AI's rounds with its reasons, the rival's grid search, and every candidate ranked.

TEST

Hold-Out Test

How the choice did, once, on the test season: our pick against the goal, why the scores differ from Model Selection, how close each method got, and the takeaways in cricket terms.

Two scores less than 0.5 runs apart are called too close to call. The graph, the tabs and the data grid are general-purpose components, written so the next seven apps can reuse them.

Part 5

How it is built and shipped

The code

Everything for this app sits in one folder: the API, the agent, the data, the preparation script, the page and the tests. Each feature was planned with Spec Kit before it was built.

Deployment

One Vercel project serves the static page and the Python function, with a 90-second limit per run. The model key and settings live on the server only.
