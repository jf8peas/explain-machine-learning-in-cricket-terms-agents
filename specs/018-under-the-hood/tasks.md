## Dependencies

- Phase 1 → Phase 2 (T004 → T005 → T006) → stories. T005 gates all main-page edits.
- **US1** (T007–T009) needs only T005. It is the MVP and is independent of the new page.
- **US2** (T010–T016) needs T006 and builds the whole static page in order (one file, so sequential). **US3** (T017–T022) needs the page file (T015); `panels.ts` and its test (T017, T018) are independent and can start at once. **US4** (T023–T027): `figures.ts` and its test (T023, T024) need only T003; the DOM and wiring need the page (T012) and the panels wiring (T020). **US5** (T028–T029) comes last because it checks the finished page.
- T019 and T012 edit the same HTML file as T010–T014, so the page-writing tasks run in order.

## Parallel opportunities

- T002 and T003 are independent of each other and of T004.
- T017/T018 and T023/T024 are pure modules with their own tests and can be done alongside the page-writing tasks (T010–T014).
- T009, T016, T022, T027 and T029 are Playwright tests added to one spec file, so write them one after another but run them in parallel; T030 is independent of everything.

## Implementation strategy

1. **MVP** = Phases 1, 2 and 3: the shared theme, the second entry and the two header links. The links are useful on their own once the page exists, so the practical release is through US2.
2. Add US2 (the page), US3 (panels) and US4 (live figures) in that order; run Vitest after each pure module and Playwright at the end of each story.
3. Finish with US5 and polish. The full Playwright suite starts its own API server, so stop anything on port 8000 first.
