# Tasks: A Realistic Setup and a Steadier Judge

**Input**: Design documents in `specs/008-realistic-setup-rolling-validation/` (plan.md, spec.md, research.md, data-model.md, contracts/api.md, quickstart.md)
**Tests**: Included, written before the code they cover. Every test uses the scripted fake model; **no test may reach the network** (only T006 downloads data, and only to refresh the files, and only the owner-run live check in T034 calls a model).
**Paths**: Relative to `apps/linear_regression/` unless they start with `specs/`.
**No new dependencies.** Every command runs from `apps/linear_regression/` (web commands from `web/`). On this machine start the API with `uv run python -m uvicorn ...` (the `uvicorn.exe` launcher is blocked by Windows policy). Write files with the Write tool; bash heredocs with quotes and backslashes fail here.

## Format: `- [ ] [ID] [P?] [Story?] Description with file path`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: user story label (US1 to US6), used only in story phases

**Story map** (spec.md): US1 everyone judged on the same realistic innings (P1); US2 a steadier judge, three rolling checks (P1); US3 the language model chooses a full setup (P1); US4 a fair rival, a visible grid search and the first hyperparameters (P2); US5 the visitor can read the winning setup (P2); US6 the data carries what the new choices need, the stages stay correct (P2).

**Build order note**: the suite must stay runnable after every task. Phase 2 adds the new modules (settings, columns, rolling checks, fast fitting) beside the old code without wiring them in. US1 applies the population to the introduction. US2 swaps the single validation year for the three checks in the agent, using one fixed default setup (all years, no weighting, test-population innings) until US3 lets the model choose; US3 adds the choosing; US4 swaps the self-looping `forward_selection` for the one-visit `grid_search` and moves the validation-based winner there; US5 and US6 are the page and the Data tab. The old `split_three_ways` is removed last, in Polish, once nothing calls it.

## Implementation strategy

1. **Safe first step**: T001 records what passes today and the visible-word count.
2. **Foundations without wiring**: Phase 2 gives the settings, the refreshed data, the rolling-checks function and the fast exact fit, all tested beside the old code, so nothing visible changes and the suite stays green.
3. **Judging first**: US1 and US2 are the minimum that is correct and honest: the right innings, three checks, the winner chosen without the test year. They run with one fixed default setup.
4. **The choosing**: US3 lets the model choose, US4 makes the rival a complete visible grid and explains hyperparameters.
5. **The page**: US5 and US6 show it all and fix the Data tab.
6. **Finish**: remove the old split, docs, the full runs, the owner's review, the live-model check and the reader review.
7. Throughout: the test year is read only in `final_test`, every number comes from code, every menu id, label, member name and half-life lives in `setup_settings.py`, no new dependency, no test reaches the network.
