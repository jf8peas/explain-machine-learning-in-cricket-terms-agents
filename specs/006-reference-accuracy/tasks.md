## Notes from building

- **`scoring.py` (new, app-specific)**: `final_test` hands its fitted models to one module that scores the four methods, builds the identical-pairs list, the large-bias finding, the reference finding, the verdict and the chart points. The plan listed only `nodes.py` for this; a module keeps `final_test` short and lets the helpers be tested on made-up numbers.
- **More words and figures in the final state than planned**: `bias_words` (per method), `bias_sentence`, `verdict_sentence`, `versus_know_nothing` (the winner against the know-nothing guess, so every number in the explanation is in the state) and `tolerances` (so "within 10 runs" is a figure in the state too). `goal.compare()` is the shared arithmetic behind `verdict()` and `versus_know_nothing`.
- **The page types no wording**: the introduction's bias cells, the results table's bias column, the verdict and the large-bias sentence all come from `accuracy_text.py` and `goal.py`. `GET /api/reference` therefore carries `words` (the bias in full and short form) as well as `sentences`.
- **Percentages from displayed figures**: the introduction's gap is 25.9% (7.6 runs of 29.4), worked out from the rounded figures, not 25.7% as the unrounded training figures give; research.md's earlier figure was from the unrounded values.
- **The introduction block sits beside the goal** in a two-column row instead of stacking under it, so it adds little height: Play's bottom edge is about 740 px in a 1280 × 800 window (limit 784).
- **The leaderboard table now scrolls inside its own box**: at phone width it was 6 px wider than the screen once a run had finished, which the new phone test found. Its own fix, not part of the plan.
- **`cricket_explanation.py` takes the new sentences as parameters** (`comparison_sentences`, `verdict_sentence`) because it is a shared-library candidate and must not import app-specific wording.
- **Existing tests changed on purpose**: `test_final_test.py` (the verdict is worked out from displayed one-decimal figures), `test_explanation_numbers.py` (numbers are compared by size, since a sentence says "1.1 runs too low" where the state holds -1.1) and `panels.spec.ts` (the baseline step now also changes `reference_validation`).
- **Playwright**: nothing else needed adjusting; the worker cap and long timeouts from feature 005 still apply.
- **A flaky test was really a test bug, now fixed**: two `play.spec.ts` tests pressed Play and then called `playToEnd`, which pressed it again. Play is disabled while a run is in progress (feature 004), so the second press waited, then started a second run as the first ended, and which run the test saw depended on timing. They now use a new `finishRun` helper that waits without pressing Play. The suite passed three full runs in a row afterwards.
- **The introduction's table** has wrapping column headings and tighter padding so it fits in a 1280 px window without scrolling (a test checks it); Play's bottom edge is at 750 px.
